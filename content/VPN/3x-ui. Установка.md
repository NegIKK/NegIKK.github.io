разворачиваем 3x-ui стандартной командой

```python
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
```

Команда для выбора конкретной версии приложения

```
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh) v3.4.0
```

после этого переходим к фаерволу. Устанавливаем разрешенные порты:

- 22 - порт для ssh, через него сидим в консоли
- 80 - стандартный порт. он нужен для получения SSL сертификатов
- 443 - стандартный порт, так же может быть нужен для сертификатов. Но он так же нужен, так как через него идет подключение к впн. Это доп маскировка
- 2026 - это порт для доступа к панели настроек. Устанавливается при развертывании самостоятельно или рандомно. У каждого свой
- 2096 - стандартный порт для подписок, если юзаете

```
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 2026/tcp
ufw allow 2096/tcp
ufw allow 9000:9020/tcp
ufw enable
```

Для проверки какие порты в итоге открыты

```
ufw status verbose
```

Так же могут быть проблемы, если порт уже занят. Может обрываться связь в консоли, просто вылетать или выдавать ошибки. Проверить занят ли порт (например 80)

```python
sudo ss -tuln | grep :80
```

Если ничего не выдает, значит он свободен. А если выдает, то смотрим что занимает и выключаем (гуглим, если это еще законно)

# SSL сертификат

Используем либо купленный домен, либо тот что шел вместе с сервером. Так же можно использовать и просто ip.

Если используем покупной сторонний, то после привязки его к IP сервера ждем некоторое время, хотя бы 15-20 минут. Проверить связан ли он с нашим сервером можно через терминал винды. Он отобразит и домен и IP, если он верный - то все связалось и можно делать ключ.

Домен записываем свой. тут мой

```python
ping kenigg.space
```

## Если что-то идет не так

![[Заметки/files/Pasted image 20260601130611.png|700]]
Может быть так, что ключ не смог записаться и он битый либо есть файл, но он пустой. Тогда в x-ui выбираем пункт `force renew`. В ином случае он посчитает, что ключ уже есть и не поменяет его.

Проверить состояние ключа. Где `kenigg.space` заменяем на имя вашего домена.

```python
ls -lh ~/.acme.sh/kenigg.space_ecc/
```

Размер файлов должен быть больше 0. Если 0, то они пустые. Так же можно посмотреть их содержимое через `cat`.

После того как сделали `force renew` выбираем `Set Cert paths for the panel` иначе новый ключ не применится.

# Правильная маскировка (Рекомендуется)

В идеале надо при создании подключения делать правильную маскировку под сайт, который находится "рядом" с вашим ip. Для этого надо просканировать ближайшие адреса. Для этого используем [RealiTLScanner](https://github.com/XTLS/RealiTLScanner). Скачиваем его себе на ПК, распаковываем и открываем в этой папке терминал (обычно по нажатии в папке правой кнопкой с удерживаемым alt).

После чего вставляем команду

```python
./RealiTLScanner.exe -addr 1.1.1.0/24 -thread 100
```

- RealiTLScanner.exe - точное название исполняемого файла в папке. Скорее всего оно будет немного иным
- IP используем ваш, с добавлением 0/24 вместо последнего числа. Таким образом будут просканированы 255 адресов в этом пуле

После этого получим стену текста. Его можно скопировать в блокнот или другое удобное место. Там через поиск ищем `cert-domain=` После него будут адреса. Проверяем приглянувшиеся и смотрим что там. В моем случае попался ign.com. Он хорошо сработал. Не все срабатывают, иногда не получается подключиться с клиента если указаны неподходящие домены.
